## Goal

Ship the "Add Strategy" flow the spec opens with: write or paste Python, see SDK-aware autocomplete and inline
lint diagnostics, save an immutable version, and launch a backtest — without ever leaving the page.

## Scope

**In scope**
- `features/strategy-studio`:
  - Monaco editor with Python language support, tuned options (minimap off, 4-space tabs, `wordBasedSuggestions`
    from the SDK), and a dark theme matching the app.
  - SDK completion provider: `BaseStrategy`, `generate_signals`, `on_bar`, `params`, `Signal`, plus the whitelisted
    library surface — generated from `docs/contracts/strategy-sdk.md` + a checked-in `sdk-stubs.d.ts`-style
    snippet (single source, regenerated by `make web-sdk-stubs`).
  - Diagnostics: `POST /api/v1/strategies/validate` on debounce (700 ms) + explicit "Validate"; render errors/warnings
    as Monaco markers (`IMPORT_FORBIDDEN`, `LOOKAHEAD_SHIFT`, …) with hover messages and a bottom panel listing
    rule id + docs link.
  - Params editor: typed key/value grid (number/string/bool) derived from the strategy's `params` defaults
    (parsed from AST metadata returned by the API), with validation and "add param".
  - Save flow: name + description + code + params → `POST /strategies` (new) or `POST /strategies/{id}/versions`
    (edit); show the new version number and "no changes to code" idempotency message.
  - "Run backtest" panel: timeframe, from/to, universe (all / sector checkboxes / symbols), `allow_partial`;
    submits `POST /backtests/run`, navigates to `/backtests/:runId`.
  - Template insertion: "Insert template" loads `GET /strategies/template`; unsaved-changes guard on route exit.
- Editor state persistence to localStorage (per strategy id) so a refresh doesn't lose work; explicit "discard"
  action.
- Sanitisation: code is only ever sent to the API, never `eval`'d in the browser.

**Out of scope**
- Running/visualising results (SS-032). Paper deployment (SS-033).

## Small architecture

```text
StrategyStudioComponent
 ├─ MonacoEditorComponent (wrapper: model, markers, completions, theme)
 ├─ ValidationService (debounce -> POST /strategies/validate -> markers + panel)
 ├─ ParamsEditorComponent (typed grid, defaults from API)
 ├─ SaveService (create/version, idempotent, optimistic concurrency on current_version)
 └─ RunBacktestPanelComponent (form -> POST /backtests/run)
```

* The editor wrapper owns exactly three responsibilities: model lifecycle (dispose/create model per strategy),
  marker updates, and completion registration. Everything else stays out of Monaco's way.
* Debounced validation is cancelled on save and on route change (`AbortController`) so stale diagnostics never
  overwrite newer results.
* Optimistic concurrency: send `expected_current_version`; a `409` shows "someone else saved a newer version" with
  a diff hint (the API returns the current version number).
* Unsaved-changes guard uses `canDeactivate` and stores the draft in localStorage on every change (debounced).

## Acceptance criteria

1. "Add Strategy" opens the studio pre-filled with the SDK template and the editor reports Python syntax
   highlighting.
2. Typing `BaseStrategy` or `def generate_signals` shows SDK completions with docstrings; unknown APIs don't
   suggest anything bogus.
3. Pasting `import os` surfaces an inline error marker on line 1 within 1 s and disables Save.
4. `df['close'].shift(-1)` surfaces a `LOOKAHEAD_SHIFT` error marker at the correct line/column; `shift(1)` does not.
5. Saving creates version 1 and shows the version number; saving unchanged code returns the same version with an
   "identical code" message (no duplicate version).
6. A `409` from a concurrent save shows the "newer version exists" message and does not clobber the server state.
7. Refreshing the page restores unsaved drafts; navigating away with unsaved changes prompts.
8. The Monaco chunk is lazy-loaded (initial bundle unchanged) and the studio passes axe accessibility basics
   (labels, focus order).

## Test plan

## Notes / risks

- Editor diagnostics can thrash if validation runs per keystroke; debounce + cancellation + "only render changed
  markers" is required to keep typing smooth.
- Monaco adds ~1 MB; lazy-load it behind the route or the chart page's first paint suffers.
